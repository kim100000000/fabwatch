## 2. 시각/타임존 — 통과
- 프론트 datetime-local(KST) → `kstLocalToUtcIso`(`+09:00` 부여 후 toISOString) → 서버 Instant 파싱 OK. 응답은 UTC `Z`(jackson write-dates-as-timestamps=false, time-zone UTC) → 화면 `formatKst`(Asia/Seoul) 변환.
- 교대: 서버 `ShiftUtil.isDayShift`(KST 8<=h<20) == 프론트 `currentShift`(hour>=8 && <20, en-US hour12=false에 `%24` 처리) — 경계 일치.
- 미래 시각: 서버 `endedAt > now+1분` 400(InspectionService.java:203), 프론트는 시작·종료 모두 `> Date.now()` 즉시 차단(허용치 없음, 더 엄격) → 충돌 없음. 기본값 end=현재 분 절삭이라 항상 통과.
- from/to: 서버 `startedAt >= from AND < to`. 프론트 `kstDateToUtcIso(end)` = 종료일 `23:59:59.999+09:00` → 종료일 전체 포함(off-by-one 없음, 23:59:59.999~24:00 구간만 이론상 누락, 실질 무시 가능).
- 서버 `@DateTimeFormat(ISO.DATE_TIME) Instant`가 밀리초 포함 `Z` 문자열을 수용(통합 테스트에서 `Instant.toString()`로 검증).

## 4. PM 지연 알람 이벤트 경로 — 통과 (테스트 갭 MED-2)
- (a) 원자성: `PmOverdueService.publishOverdueEvents`(@Transactional) → `eventPublisher.publishEvent` → `AlarmService.onPmOverdue`는 **`@EventListener`(동기) + @Transactional(REQUIRED)** (AlarmService.java:~90). `@TransactionalEventListener(AFTER_COMMIT)`가 아니므로 알람 생성 예외 시 같은 트랜잭션이 롤백되어 `overdue_alarm_sent=true`도 롤백, 다음 정각에 재시도. "플래그만 true로 남는 영구 누락" 결함 없음.
- (b) 조건/중복 억제: 쿼리 `next_due < now-3일 AND overdue_alarm_sent=false`(PmScheduleRepository) = `isAlarmDue`(정확히 3일은 제외, 테스트로 확인). 억제는 `existsByEquipmentIdAndAlarmTypeAndStatusNot(PM_OVERDUE, RESOLVED)`로 유형 기준 — 수동 MAJOR 알람과 서로 가리지 않음(AlarmInspectionLinkTest). 메시지 `{설비코드} PM 예정일 경과 (n일)`, MAJOR → CRITICAL 아님 → 자동 DOWN 이벤트 없음.
- (c) 스케줄러: `PmOverdueScheduler`는 `@Scheduled(cron="0 10 * * * *", zone="UTC")`이며 `@EnableScheduling`이 `SchedulerConfig`의 `@ConditionalOnProperty(fabwatch.scheduler.enabled, matchIfMissing=true)` 아래에 있어 `enabled=false`(application-test.yml:21)에서 비활성. 통과.
- (d) 재발행: `PmSchedule.markDone`/`reschedule` 모두 `overdueAlarmSent=false`. PM 등록 시 `refreshPmSchedule`이 markDone 호출(소급 건 제외) → 다음 지연 때 재발행 가능(PmOverdueServiceTest.republishesAfterPmDone).
- 관찰(LOW-6): PM 수행으로 일정이 갱신되어도 기존 OPEN PM_OVERDUE 알람은 자동 해제되지 않음(스펙 미정의). 사용자가 ACK→RESOLVE 해야 하며, 미해제 알람이 남아 있으면 다음 지연 때 유형 중복 억제로 새 알람이 생성되지 않음(플래그는 true가 됨).
- 관찰(LOW-7): 이벤트가 스케줄 단위 루프라 한 스케줄의 알람 생성 예외가 전체 배치를 롤백 → 매시 같은 실패 반복(poison pill). 현재 raise 경로에서 실패할 요인은 적어 LOW.
