# QA 리포트 — S-2/S-3 프론트 연결 (2026-08-09)

> 참고: 서브에이전트(mes-qa)가 검증 도중(수정 적용 단계) 워치독 타임아웃으로 중단됨(600초 무응답).
> 작업트리는 빌드/린트 정상이었고, 이 리포트는 리더(오케스트레이터)가 핵심 위험 항목을 직접 재검증해 작성함.
> 서브에이전트가 실제로 무엇을 수정했는지 커밋 이력이 없어 특정 불가 — 대신 최종 상태를 전수 대조함.

## 통과 (직접 대조 완료)

- **상태 전이표 일치**: 백엔드 `EquipmentStatus.java`(RUN↔IDLE↔DOWN↔PM, EnumMap) vs 프론트 `types.ts`의 `ALLOWED_STATUS_TRANSITIONS` — 완전 일치 (RUN:[IDLE,DOWN,PM] / IDLE:[RUN,DOWN,PM] / DOWN:[PM] / PM:[IDLE])
- **에러 코드 완전성**: 백엔드 `ErrorCode` 12개 전부 확인. 프론트 `errorMessage.ts`에 10개 매핑 + `NOT_FOUND`/`VALIDATION_ERROR`/`INVALID_STATUS_TRANSITION` 3개는 "서버 message가 더 구체적"이라는 이유로 의도적 미매핑(주석 명시, 폴백 동작 확인) — 누락 아님
- **GET /equipments/{id}/status-logs 응답 shape**: 백엔드 `EquipmentStatusLogResponse`(id,equipmentId,fromStatus,toStatus,reason,changedBy,changedByName,changedAt) vs 프론트 `EquipmentStatusLog` 타입 — 필드명·nullable 전부 일치. `.content` unwrap도 정상
- **권한 매트릭스**: 백엔드 `@PreAuthorize` — POST/PUT `hasRole('ADMIN')`, PATCH status `hasAnyRole('ADMIN','ENGINEER')` vs 프론트 `canManage/canEdit`(ADMIN), `canChangeStatus`(ADMIN·ENGINEER) — 정확히 일치. 버튼 숨김과 서버 403 기준이 어긋나지 않음
- **soft delete 위반 없음**: `equipment/` 패키지에 물리 delete 호출 없음
- **실설비 물리 제어 코드 없음**: PLC/Modbus 문자열은 안전 경고 주석(`docs/11 §10` 인용) 1건뿐, 실제 구현 없음
- **TECHNICIAN 명칭 유지**: `Role.java`, `frontend/features/auth/types.ts` 모두 MAINTENANCE로 바뀌지 않음(주석으로 명시)
- **빌드/린트**: `npm run build`(tsc 포함) 성공 125 modules, `oxlint` 0 warnings/0 errors

## 미검증

- **런타임 E2E 미실시** — 백엔드 서버 미기동 상태로 코드 대조만 수행. 실제 등록 시 409 중복코드, PATCH 시 400 전이거부 UX는 서버 기동 후 1회 수동 확인 권장 (프론트 1차 보고에서도 동일하게 명시됨)
- **서브에이전트가 워치독 중단 전 실제로 어떤 파일을 손댔는지는 커밋 단위로 특정 불가** — 다만 위 대조 결과 최종 상태에 결함이 없으므로 리스크로 보지 않음
