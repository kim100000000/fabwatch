# 14. 용어사전 (Glossary) — FabWatch

> 버전 v1.0 / 2026-07-07
> 목적: 문서·코드·면접에서 용어를 **일관되게** 쓰기 위한 단일 출처. docs/02 §2 용어 정의를 확장·통합한다.
> 우선순위 충돌 시: 도메인 규칙은 docs/03, 데이터 정의는 docs/05, API 명칭은 docs/06이 우선.

## 1. 설비 보전(Maintenance) 용어 — 현장 기반

| 용어 | 영문/약어 | 정의 | 비고 |
|---|---|---|---|
| 예방정비 | PM (Preventive Maintenance) | 주기 기반으로 미리 하는 정비(주간/월간 PM 등) | 고장 전 조치 |
| 돌발정비 | BM (Breakdown Maintenance) | 고장 발생 후 수행하는 수리 | 4M 원인 분류 필수 |
| 평균 고장 간격 | MTBF (Mean Time Between Failures) | Σ(가동시간) / 고장(DOWN 전환) 횟수 | KPI. DOWN 0회면 "고장 없음" |
| 평균 수리 시간 | MTTR (Mean Time To Repair) | Σ(DOWN 진입~DOWN 이탈) / 고장 횟수 | KPI |
| 가동률 | Availability | RUN 시간 / (전체 시간 − PM 시간) | 분모에서 PM 제외 |
| 4M | Man/Machine/Material/Method | 고장 원인 분류 체계 | BM 등록 시 필수 선택 |
| 교대조 | Shift (D/N) | 주간(D)/야간(N) 근무조. 이력·리포트 기본 구분 | D=08:00~20:00, N=20:00~08:00 (KST) |
| 인터락 | Interlock | 안전/품질 조건 미충족 시 가동을 막는 안전 개념 | 본 시스템에선 CRITICAL 알람 시 자동 DOWN으로 반영 |
| 시운전 | — | 정비 후 정상 확인을 위한 임시 가동 | 상태머신에서 PM→IDLE 경유(바로 RUN 불가)로 표현 |
| 점검 이력 | Inspection | PM/BM 수행 기록(작업자·교대·소요시간·조치) | 시스템 핵심 1 |
| 체크리스트 | Checklist | 설비별 PM 점검 항목 템플릿(OK/NG/NA 판정) | NG 1건이면 이력에 NG 플래그 |

## 2. 설비 상태 & 알람 용어

| 용어 | 값 | 의미 |
|---|---|---|
| 설비 상태 | RUN / IDLE / DOWN / PM | 가동 / 대기 / 고장정지(BM, 계획 외 정지) / 정비중(PM, 계획된 정지) |
| 상태 머신 | — | 허용된 상태 전환만 가능한 규칙(docs/03 F-2). 위반 시 `INVALID_STATUS_TRANSITION` |
| 상태 로그 | equipment_status_logs | 모든 상태 전환 기록. **KPI 계산의 원천** |
| 알람 심각도 | WARNING / MAJOR / CRITICAL | 경고 / 주요 / 위험. CRITICAL은 자동 DOWN 유발 |
| 알람 상태 | OPEN → ACK → RESOLVED | 발생 → 확인 → 조치완료. ACK 없이 RESOLVED 불가 |
| 알람 유형 | SENSOR_THRESHOLD / PM_OVERDUE / MANUAL | 임계치 초과 / PM 지연 / 수동 보고 |
| 중복 억제 | Deduplication | 동일 설비+센서+심각도의 미해결 알람이 있으면 신규 생성 안 함 | 알람 폭주(현장 최악) 방지 |
| PM 지연 | OVERDUE | 예정일(next_due_at) 경과 상태. 3일 초과 시 MAJOR 알람 |
| ACK | Acknowledge | 알람 확인 처리(담당자 기록) |

## 3. 센서 & 임계치 용어

| 용어 | 정의 |
|---|---|
| 센서 종류 | TEMP(온도℃) / VIBRATION(진동 mm/s) / PRESSURE(압력 kPa) / CURRENT(전류 A) |
| 기준값 / 노이즈 | base_value / noise_sigma — 시뮬레이터의 정상 패턴 파라미터(평균 ± 가우시안) |
| 임계치 | warn_low / warn_high / crit_low / crit_high (경고·위험 상하한). `crit_low ≤ warn_low < warn_high ≤ crit_high` |
| 이상 시나리오 | DRIFT(점진 상승) / SPIKE(순간 급등) / STEP(단차) — 시뮬레이터 주입용 |
| 원본 데이터 | sensor_data — 2초 주기 원본, 7일 보관 |
| 1분 집계 | sensor_data_1m — 분 단위 min/max/avg, 영구 보관 |
| 다운샘플링 | granularity RAW/1M — 조회 기간에 따라 원본/집계 자동 선택 |
| 슬라이딩 윈도우 | 실시간 차트가 최근 N분만 유지하는 방식(최근 5분/최대 150포인트) |

## 4. 시스템 · 아키텍처 용어

| 용어 | 정의 |
|---|---|
| MES | Manufacturing Execution System. 생산 실행 시스템. 본 프로젝트는 그 중 설비관리 모듈 |
| 모듈러 모놀리스 | 단일 배포지만 도메인별로 강하게 분리한 구조(MSA 아님). 근거 docs/10 ADR-1 |
| 도메인 우선 패키지 | 레이어(controller/service)가 아닌 도메인(equipment/sensor…)으로 먼저 나눈 패키지 구조 |
| 도메인 이벤트 | 도메인 간 직접 참조 대신 스프링 이벤트로 통신(예: ThresholdExceededEvent → alarm 모듈) |
| FSD 라이트 | 프론트 구조: app/pages/features/shared. 백엔드 도메인과 features 1:1 |
| SSE | Server-Sent Events. 서버→클라이언트 단방향 실시간 푸시(WebSocket 아님) |
| JWT | Access(30분) + Refresh(14일, DB 저장) 토큰 인증 |
| soft delete | 물리 삭제 대신 deleted_at 기록(이력 시스템 원칙) |
| 멀티테넌트 | 여러 고객사 데이터 격리 구조. 현재는 미구현, tenant_id 추가 지점만 `// TENANT:` 표시 |
| 쿼터 | AI 리포트 일일 생성 한도(기본 20건). 초과 시 `AI_QUOTA_EXCEEDED` |
| DRAFT / CONFIRMED | AI 리포트 초안 / 확정본. 원본(draft_content)과 확정본(final_content) 분리 보존 |

## 5. 역할 용어 (혼동 주의)

| 용어 | 정의 | 주의 |
|---|---|---|
| ADMIN / ENGINEER / TECHNICIAN | 시스템 역할 코드(사람) | 권한 매트릭스는 docs/11 §3 |
| TECHNICIAN | 테크니션(현장 작업자 역할) | **MAINTENANCE로 바꾸지 않는다** — 역할=사람 |
| Maintenance(설비보전) | 업무 영역을 가리키는 용어 | 화면 메뉴·이력서 표기에서만 사용 |

## 6. 코드 마커 규약

| 마커 | 의미 |
|---|---|
| `// TENANT:` | 멀티테넌트 전환 시 tenant_id 추가가 필요한 지점 |
| `// SCALE:` | 단일 인스턴스 전제 로직(스케일아웃 시 재검토 필요, 예: @Scheduled) |

## 7. 에러 코드 색인 (전체 정의는 각 문서)

| 코드 | 상황 | 출처 |
|---|---|---|
| `LOGIN_FAILED` / `ACCOUNT_LOCKED` / `TOKEN_EXPIRED` / `USER_DISABLED` | 인증 | docs/06 §1 |
| `FORBIDDEN` / `VALIDATION_ERROR` | 인가/입력검증 | docs/11 §3, §6 |
| `UNAUTHORIZED` (401) / `NOT_FOUND` (404) / `INTERNAL_ERROR` (500) | 인증 필요 / 대상 없음 / 처리되지 않은 서버 오류 | docs/03 F-7 |
| `METHOD_NOT_ALLOWED` (405) / `UNSUPPORTED_MEDIA_TYPE` (415) / `NOT_ACCEPTABLE` (406) | 허용되지 않는 HTTP 메서드 / Content-Type / Accept — 클라이언트 실수이므로 500이 아니라 해당 4xx로, 공통 포맷 유지 | docs/06 공통 오류 |
| `RATE_LIMITED` (429) | 로그인·리프레시 IP 레이트 리밋(분당 30, `Retry-After` 헤더) 또는 SSE 동시 연결 한도 초과. `ACCOUNT_LOCKED`(계정 잠금)와 상태코드는 같지만 코드로 구분 | docs/11 §4 |
| `PAYLOAD_TOO_LARGE` (413) | 요청 본문이 상한(기본 1MB) 초과 | docs/11 §4 |
| `CONFLICT` (409) | DB 제약 충돌(중복·참조 무결성). SQL·제약명은 노출하지 않는 고정 문구 | docs/06 공통 오류 |
| `INVALID_TOKEN` (401) | 알 수 없는/만료/폐기된 Refresh 토큰 — 서버 세션은 지우지 않음 | docs/11 §2 |
| `INVALID_THRESHOLD_RANGE` (400) | 임계치 순서 위반(crit_low ≤ warn_low < warn_high ≤ crit_high) 또는 **4값을 전부 비움**(센서 감시가 꺼짐). 자릿수(정수 8·소수 2자리) 초과는 `VALIDATION_ERROR` | docs/03 F-2, docs/06 §3 |
| `INVALID_STATUS_TRANSITION` | 상태머신 위반 | docs/03 F-2 |
| `CAUSE_4M_REQUIRED` | BM 4M 누락 | docs/06 §4 |
| `ACK_REQUIRED_FIRST` | ACK 없이 resolve | docs/06 §6 |
| `AI_QUOTA_EXCEEDED` (403) | AI 일일 생성 한도 초과 (생성·재시도) | docs/06 §7 |
| `ALREADY_GENERATING` (409) | 같은 알람/점검에 GENERATING 리포트가 이미 있음 | docs/06 §7 |
| `INVALID_REPORT_STATE` (409) | 리포트 상태가 허용하지 않는 PUT/confirm/retry | docs/06 §7 |

> 새 용어·에러 코드가 생기면 이 문서에 추가하고, 정의가 바뀌면 원천 문서와 함께 갱신한다.
