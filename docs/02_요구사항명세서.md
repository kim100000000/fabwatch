# 02. 요구사항 명세서 (SRS) — FabWatch

> 버전 v1.0 / 2026-07-06 / MVP 범위 한정

## 1. 시스템 구성

```
[브라우저 (테크니션/엔지니어/관리자)]
        ↕ HTTPS / SSE
[프론트엔드: React 18 + TypeScript + Vite]
        ↕ REST API + SSE
[백엔드: Spring Boot 3.x (Java 17)]
   ├─ 인증(JWT) / 설비·점검·알람 도메인
   ├─ 센서 시뮬레이터 (@Scheduled, 내장 모듈)
   ├─ SSE 브로드캐스터 (실시간 센서/알람 푸시)
   └─ AI 리포트 서비스 → [Claude API]
        ↕ JPA
[MySQL 8.x]
```

## 2. 용어 정의

| 용어 | 정의 |
|---|---|
| PM | Preventive Maintenance. 주기 기반 예방정비 (예: 주간 PM, 월간 PM) |
| BM | Breakdown Maintenance. 고장 발생 후 수행하는 돌발정비 |
| 설비 상태 | RUN(가동) / IDLE(대기) / DOWN(고장정지) / PM(정비중) 4단계 |
| 알람 | 센서값 임계치 초과 또는 수동 보고로 발생하는 이벤트. 심각도 WARNING / MAJOR / CRITICAL |
| 인터락 | 안전/품질 조건 미충족 시 설비 가동을 막는 개념. CRITICAL 알람 시 상태 자동 DOWN 처리로 반영 |
| MTBF | 평균 고장 간격 = 총 가동시간 / 고장 횟수 |
| MTTR | 평균 수리 시간 = 총 수리시간 / 고장 횟수 |
| 가동률 | RUN 시간 / (전체 시간 − PM 시간) |
| 교대조 | 주간(D)/야간(N) 근무조. 이력·리포트의 기본 구분 단위 |
| 4M | 고장 원인 분류: Man / Machine / Material / Method |

## 3. 사용자 역할 및 권한

| 역할 | 코드 | 권한 |
|---|---|---|
| 관리자 | ADMIN | 전체 + 사용자 관리 + 설비 마스터 등록/수정 + 임계치 설정 |
| 엔지니어 | ENGINEER | 점검 이력 승인, PM 스케줄 관리, AI 리포트 생성/확정, 알람 조치 |
| 테크니션 | TECHNICIAN | 점검 이력 등록, 알람 확인(ACK), 대시보드 조회 |

## 4. 기능 요구사항 (FR)

우선순위: M(Must, MVP 필수) / S(Should, 시간 되면) / C(Could, 확장)

### FR-1 인증/사용자
| ID | 요구사항 | 우선순위 |
|---|---|---|
| FR-1.1 | 이메일+비밀번호 로그인, JWT(Access+Refresh) 발급 | M |
| FR-1.2 | 역할 기반 접근 제어 (ADMIN/ENGINEER/TECHNICIAN) | M |
| FR-1.3 | 관리자의 사용자 등록/비활성화 | S |

### FR-2 설비 마스터
| ID | 요구사항 | 우선순위 |
|---|---|---|
| FR-2.1 | 라인 > 공정 > 설비 3계층 구조 등록/조회/수정 | M |
| FR-2.2 | 설비별 상태(RUN/IDLE/DOWN/PM) 관리 및 상태 변경 이력 기록 | M |
| FR-2.3 | 설비별 센서 및 임계치(경고/위험 상하한) 설정 | M |
| FR-2.4 | 설비 상세: 기본 정보 + 최근 알람 + 최근 점검 + 센서 현황 통합 뷰 | M |

### FR-3 점검 이력 (핵심 1)
| ID | 요구사항 | 우선순위 |
|---|---|---|
| FR-3.1 | 점검 이력 등록 (유형 PM/BM, 교대조, 작업자, 소요시간, 내용, 조치) | M |
| FR-3.2 | PM 체크리스트 템플릿 (설비별 항목 정의, 점검 시 OK/NG/NA 체크) | M |
| FR-3.3 | PM 스케줄: 주기(일/주/월) 설정 → 예정일 자동 계산, 지연 시 경고 표시 | M |
| FR-3.4 | BM 등록 시 고장 원인 4M 분류 + 알람 연계(어떤 알람으로 발생했는지) | M |
| FR-3.5 | 이력 검색/필터 (설비, 기간, 유형, 교대조, 작업자) + 페이징 | M |
| FR-3.6 | 엔지니어의 이력 승인(검토 완료 표시) | S |
| FR-3.7 | 사진 첨부 | C |

### FR-4 센서 시뮬레이터
| ID | 요구사항 | 우선순위 |
|---|---|---|
| FR-4.1 | 설비당 4종 센서(온도/진동/압력/전류) 데이터를 2초 주기 생성 | M |
| FR-4.2 | 정상 패턴: 설비별 기준값 ± 가우시안 노이즈 | M |
| FR-4.3 | 이상 시나리오 주입 API: DRIFT(점진 상승) / SPIKE(순간 급등) / STEP(단차) | M |
| FR-4.4 | 시나리오 해제(정상 복귀) API | M |
| FR-4.5 | 데모 모드: 시연용 자동 시나리오(정상 30초 → 드리프트 → 알람) | S |

### FR-5 실시간 대시보드 (핵심 2)
| ID | 요구사항 | 우선순위 |
|---|---|---|
| FR-5.1 | 라인 전체 현황: 설비 카드(상태 색상, 현재 센서값, 미조치 알람 수) | M |
| FR-5.2 | 설비별 센서 실시간 차트 (SSE 푸시, 최근 5분 슬라이딩 윈도우) | M |
| FR-5.3 | 센서 이력 차트 (기간 선택 조회, 집계 다운샘플링) | M |
| FR-5.4 | 임계치 초과 시 알람 자동 생성 (WARNING/MAJOR/CRITICAL) + 실시간 토스트 | M |
| FR-5.5 | 알람 목록: 상태(발생/확인/조치완료), ACK 처리, 필터 | M |
| FR-5.6 | CRITICAL 알람 시 설비 상태 자동 DOWN 전환 (인터락 반영) | M |
| FR-5.7 | KPI 위젯: 설비별 MTBF/MTTR/가동률 (일/주/월) | S |

### FR-6 AI 고장 리포트 (핵심 3)
| ID | 요구사항 | 우선순위 |
|---|---|---|
| FR-6.1 | 알람/BM 건에 대해 "AI 리포트 생성" 실행: 알람 정보 + 전후 센서 데이터 요약 + 최근 점검 이력을 프롬프트로 구성해 Claude API 호출 | M |
| FR-6.2 | 리포트 구조: 현상 요약 / 센서 데이터 분석 / 추정 원인(4M) / 권장 조치 / 재발 방지 제안 | M |
| FR-6.3 | 생성된 리포트를 사용자가 수정 후 확정 저장 (AI 초안 ≠ 최종본, 원본 초안도 보존) | M |
| FR-6.4 | 리포트 목록/상세 조회, 마크다운 렌더링 | M |
| FR-6.5 | 교대조 인수인계 요약: 해당 교대의 알람+점검+조치를 AI가 요약 | S |
| FR-6.6 | API 실패/타임아웃 시 재시도 및 실패 사유 표시 (수동 작성 폴백) | M |

## 5. 비기능 요구사항 (NFR)

| ID | 항목 | 기준 |
|---|---|---|
| NFR-1 | 실시간성 | 센서 생성 → 화면 표시 지연 3초 이내 (SSE) |
| NFR-2 | 데이터량 | 센서 데이터 2초×4센서×5설비 ≈ 일 43만 건. 원본 7일 보관 + 1분 집계 테이블 영구 보관 |
| NFR-3 | 보안 | JWT 만료(Access 30분/Refresh 14일), 비밀번호 BCrypt, API 키는 환경변수 |
| NFR-4 | AI 비용 | 리포트 1건당 토큰 상한 설정, 호출 로그 기록. 데모용 일일 호출 제한 |
| NFR-5 | 배포 | 백엔드+DB: Railway(또는 동급), 프론트: Vercel. 무료/저비용 티어 |
| NFR-6 | 테스트 | 핵심 도메인(임계치 판정, PM 스케줄 계산, KPI 계산) 단위 테스트 필수 |
| NFR-7 | 확장성 표식 | 멀티테넌트 전환 포인트(tenant_id 추가 위치)를 코드 주석 `// TENANT:` 로 표시 |

## 6. 제약사항

- 실제 설비/PLC 연동 없음 (시뮬레이터로 대체, 인터페이스는 추상화하여 교체 가능하게)
- 1인 개발, 1개월. Must 항목 완료가 최우선, Should는 3주차 이후 여유 시
- AI API는 Claude(Anthropic) 사용. 키 노출 금지 — 반드시 백엔드 경유
