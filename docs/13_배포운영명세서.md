# 13. 배포·운영 명세서 — FabWatch

> 버전 v1.0 / 2026-07-07
> 근거: docs/02 NFR-5(Railway+Vercel 저비용), docs/07 4주차, docs/11 보안 명세(시크릿·CORS), CLAUDE.md 보안 규칙
> 목적: 4주차에 "URL만 주면 3분 안에 시연되는" 상태를 만들기 위한 배포·운영 기준. 포트폴리오이므로 **운영 감각을 보여주되 과설계는 하지 않는다.**

## 1. 배포 아키텍처

```
[사용자 브라우저]
      │ HTTPS
      ▼
[Vercel] ── 프론트(React/Vite 정적 빌드), 도메인 TLS 종단
      │ REST + SSE (HTTPS, CORS 허용 Origin만)
      ▼
[Railway] ── 백엔드(Spring Boot 컨테이너) + MySQL 8 (동일 프로젝트/네트워크)
      │
      ▼ (백엔드 내부 호출만)
[Anthropic Claude API]
```

- 프론트/백엔드 분리 배포. 프론트는 정적 자산, 백엔드는 상시 컨테이너.
- TLS는 Vercel/Railway가 종단 제공 → 애플리케이션은 평문 HTTP 리스닝하되 외부 노출은 HTTPS만 (보안 명세 §4).
- 무료/저비용 티어 전제. 비용 초과 리스크는 §7.

## 2. 환경 & 프로파일

| 환경 | 용도 | 프로파일 | 특이사항 |
|---|---|---|---|
| local | 개발 | `local` | docker-compose MySQL, 시뮬레이터 on, Claude 실키 or 목 |
| test | CI/테스트 | `test` | @Scheduled·시뮬레이터 off, Claude 목 (docs/12 §2) |
| prod | 배포(Railway) | `prod` | 환경변수 주입, 시드는 최초 1회만 |

- Spring: `SPRING_PROFILES_ACTIVE`로 선택. 프론트: Vite `--mode`.
- `application-{profile}.yml`은 커밋하되 **비밀값은 넣지 않는다**(플레이스홀더/환경변수 참조만). `application-local.yml`에 실값이 들어가면 `.gitignore` 대상 (보안 명세 §5).

### 백엔드 (Railway)
| 키 | 예시/설명 |
|---|---|
| `SPRING_PROFILES_ACTIVE` | `prod` |
| `DB_URL` | `jdbc:mysql://<host>:<port>/fabwatch?useSSL=true&serverTimezone=UTC` |
| `DB_USERNAME` / `DB_PASSWORD` | Railway MySQL 자격증명 |
| `JWT_SECRET` | 256bit 이상 랜덤 (보안 명세 §2) |
| `JWT_ACCESS_EXP_MIN` | `30` |
| `JWT_REFRESH_EXP_DAYS` | `14` |
| `JWT_REFRESH_GRACE_SECONDS` | `10` — 회전 직후 직전 Refresh 토큰 허용 시간(병렬 갱신 대비). 0이면 유예 없음 |
| `RATE_LIMIT_AUTH_PER_MINUTE` | `30` — `/auth/login`·`/auth/refresh` IP × 엔드포인트별 분당 허용 횟수(초과 429 `RATE_LIMITED`). 프록시 뒤에서는 `server.forward-headers-strategy=framework`(`SERVER_FORWARD_HEADERS_STRATEGY=framework`)로 실제 클라이언트 IP를 복원해야 한다 — 없으면 모든 요청이 프록시 IP 하나로 합산되어 정상 사용자도 막힌다 |
| `MAX_REQUEST_BYTES` | `1048576` — 요청 본문 상한(바이트), 초과 413 `PAYLOAD_TOO_LARGE` |
| `SSE_MAX_CONNECTIONS` / `SSE_MAX_PER_USER` | `200` / `5` — SSE 전체/사용자별 동시 연결 상한(사용자 초과분은 가장 오래된 연결 종료, 전체 초과는 429) |
| `ANTHROPIC_API_KEY` | 백엔드 전용, 프론트 번들 금지 (보안 명세 §5) |
| `AI_PROVIDER` | `claude`(기본) \| `mock`. mock은 명시 설정했을 때만 — 키가 없다고 자동 mock 금지. 키 없는 claude는 리포트 FAILED |
| `AI_MODEL` | `claude-sonnet-5-5` (기본값) |
| `AI_MAX_TOKENS` | `4096` (사고 토큰 포함 출력 상한) |
| `AI_EFFORT` | `low`(기본) \| `medium` \| `high` — 요청 `output_config.effort`. 잘못된 값이면 기동 실패 |
| `AI_TIMEOUT_SECONDS` | `60` (Claude 응답 읽기 타임아웃, connect는 10초 고정) |
| `SIMULATOR_DEMO_DURATION_MIN` | `2` (데모 자동 시작 DRIFT 지속 시간(분), 선택) |
| `SIMULATOR_PLATEAU_HOLD_MIN` | `5` — DRIFT가 목표값(plateau)에 도달한 뒤 유지하는 시간(분). 지나면 시나리오 자동 비활성화(알람·DOWN 재발 방지) |
| `SIMULATOR_MAX_LIFETIME_MIN` | `30` — STEP/SPIKE 시나리오의 최대 수명(분), 지나면 자동 비활성화 |
| `SSE_ASYNC` | `true` — SSE를 구독자별 큐+전용 스레드로 비동기 전송(수집 스레드 비블로킹). `false`는 동기 전송(테스트용, 운영 금지) |
| `SSE_QUEUE_CAPACITY` | `100` — 구독자별 대기 큐 크기. 가득 차면 느린 구독자로 보고 연결 종료 |
| `SSE_SEND_TIMEOUT_MS` | `5000` — 한 번의 전송이 이 시간 넘게 막히면 느린 구독자로 보고 연결 종료 |
| `SSE_SENDER_THREADS` | `8` — SSE 전송 전용 스레드 수 (막힌 전송은 소켓 쓰기 타임아웃까지 스레드 1개를 점유 — 한계) |
| `SENSOR_PURGE_CHUNK_SIZE` / `SENSOR_PURGE_CHUNK_PAUSE_MS` | `10000` / `100` — 원본 7일 삭제 배치의 청크(트랜잭션)당 행 수 / 청크 사이 대기(ms). 청크 상한 100,000 |
| `SENSOR_QUERY_MAX_RANGE_DAYS` / `SENSOR_QUERY_MAX_POINTS` | `31` / `20000` — 센서 이력 조회 최대 기간(일, 초과 400) / 센서당 응답 최대 포인트(초과 구간은 5분·1시간 버킷으로 다운샘플링) |
| `DB_POOL_MAX` / `DB_CONNECTION_TIMEOUT_MS` | `10` / `10000` — HikariCP 최대 커넥션 수 / 커넥션 대기 상한(ms). 무료 티어 MySQL `max_connections` 고려, 스케줄러·SSE·요청이 함께 사용 |
| `SHUTDOWN_TIMEOUT` | `20s` — graceful shutdown 시 진행 중 요청을 마무리하는 최대 시간(`server.shutdown=graceful` + `spring.lifecycle.timeout-per-shutdown-phase`). 컨테이너 종료 유예(SIGTERM→SIGKILL)보다 짧게 둔다 |
| `AI_DAILY_QUOTA` | `20` (하루(KST) 전체 호출 시도 수, 초과 시 403 `AI_QUOTA_EXCEEDED`) |
| `CORS_ALLOWED_ORIGINS` | Vercel 도메인 (콤마 구분, `*` 금지) |

> **DB 마이그레이션 메모 (refresh_tokens, 2026-10-06)**: Refresh 토큰 저장이 `users.refresh_token*` 컬럼에서 별도 `refresh_tokens` 테이블(SHA-256 해시, 다중 세션)로 바뀌었다. `users.refresh_token`·`refresh_token_expires_at` 컬럼은 더 이상 읽고 쓰지 않는다(local `ddl-auto: update`에서는 남아도 무방, prod `validate`도 DB 쪽 잉여 컬럼은 통과). **prod는 `ddl-auto: validate`라 새 테이블을 자동 생성하지 않으므로** 배포 전에 아래 DDL을 먼저 적용한다. 배포 시점에 기존 세션(옛 컬럼의 토큰)은 인식되지 않아 사용자는 한 번 다시 로그인한다.
> ```sql
> CREATE TABLE refresh_tokens (
>   id BIGINT AUTO_INCREMENT PRIMARY KEY,
>   user_id BIGINT NOT NULL,
>   token_hash VARCHAR(64) NOT NULL,
>   previous_token_hash VARCHAR(64) NULL,
>   rotated_at DATETIME(6) NULL,
>   expires_at DATETIME(6) NOT NULL,
>   last_used_at DATETIME(6) NOT NULL,
>   created_at DATETIME(6) NOT NULL,
>   updated_at DATETIME(6) NULL,
>   CONSTRAINT uk_refresh_tokens_hash UNIQUE (token_hash),
>   INDEX idx_refresh_tokens_user (user_id),
>   INDEX idx_refresh_tokens_expires (expires_at),
>   INDEX idx_refresh_tokens_prev (previous_token_hash)
> );
> ```
> (정확한 컬럼 타입은 `ddl-auto: update`로 한 번 생성된 local 스키마와 대조해 확인한다. `Flyway` 도입은 별도 작업.)

### 프론트 (Vercel) — `VITE_` 접두사는 번들 노출 전제 → 공개 가능 값만
| 키 | 설명 |
|---|---|
| `VITE_API_BASE_URL` | `https://<railway-app>/api/v1` — **프로덕션 빌드에서 필수**. 미지정 시 localhost 로 폴백하지 않고 상대경로 `/api/v1` 를 쓴다(빌드 로그에 경고). SSE(`/stream/*`)도 같은 값을 base 로 사용하므로 별도 SSE 변수는 없다 |
| `VITE_DEMO_LOGIN` | 로그인 화면의 '데모 계정' 버튼 노출 여부(`true`/`false`). 기본: 개발 모드 true, 프로덕션 빌드 false. 공개 데모에서만 `true` |

> SPA 라우팅: `frontend/vercel.json` 의 rewrites(`/(.*)` → `/index.html`)로 새로고침·딥링크(`/equipment/1`)가 404 가 되지 않게 한다.

> **커밋 전 필수:** `git status`로 `.env`/`application-local.yml` 미추적 확인. 최초 커밋 전 시크릿이 히스토리에 없는지 점검 (보안 명세 §5, CLAUDE.md).

## 4. 빌드 & 배포 절차

### 백엔드 (Railway)
1. `./gradlew clean build` (테스트 포함) → 실행 가능 jar.
2. 컨테이너 빌드: Dockerfile(다단계) 또는 Railway Nixpacks 자동 감지.
3. 환경변수 주입 → 배포. 헬스체크 `/actuator/health` 통과 확인.
4. **DB 마이그레이션**: MVP는 `ddl-auto=validate`(prod) + 수동 스키마 or Flyway 여유 시. `create/update` 금지(운영에서 스키마 자동 변경은 위험).
5. 시드: prod 최초 1회만 실행되도록 가드(플래그/조건). 시연 데이터가 매 배포마다 중복 생성되지 않게.

### 프론트 (Vercel)
1. Git 연동 → main 푸시 시 자동 빌드(`npm run build`, tsc 포함).
2. 환경변수 설정 후 배포. Preview(브랜치) / Production(main) 분리.

### CI (GitHub Actions — 여유 시, Should)
```
push/PR → ① 백엔드 ./gradlew test  ② 프론트 npm run build(tsc)
         → 통과해야 배포 (Railway/Vercel Git 연동은 별도 자동 배포)
```
- 시크릿은 GitHub Actions Secrets. 로그에 마스킹.

## 5. 운영 스케줄러 (백엔드 @Scheduled)

| 작업 | 주기 | 근거 |
|---|---|---|
| 센서 데이터 생성(시뮬레이터) | 2초 | docs/03 F-4.2 |
| 1분 집계 UPSERT (`sensor_data_1m`) | 1분 | docs/05 §3 |
| 원본 `sensor_data` 7일 초과 삭제 배치 | 일 1회 **03:30 UTC**(`@Scheduled(cron, zone="UTC")` 명시 — 이전엔 zone이 없어 JVM 타임존을 따랐다). **청크 삭제**(기본 10,000행/트랜잭션, 청크 사이 100ms 대기, 삭제 건수·소요시간 INFO 1줄) | docs/05 §3, docs/15 §7 |
| PM OVERDUE 점검 → 지연 알람 이벤트 발행 | 시간당 (매시 :10 UTC, `PmOverdueScheduler`) | docs/03 F-3.3 |

- **종료(graceful shutdown)**: `server.shutdown=graceful` + `timeout-per-shutdown-phase=20s`. SIGTERM을 받으면 새 요청은 거절하고 진행 중 요청을 최대 20초 기다린 뒤 종료한다. 열려 있는 SSE 연결은 요청으로 취급되어 종료가 타임아웃까지 걸릴 수 있다(그 뒤 강제 종료, 프론트는 재연결). AI 리포트 생성 풀은 `@PreDestroy`에서 `shutdown()` 후 최대 10초 대기하고, 넘기면 `shutdownNow()`로 중단한다(중단된 PENDING/GENERATING 건은 기동 시 복구 서비스가 FAILED로 정리).
- prod 단일 인스턴스 전제(스케줄러 중복 실행 없음). **스케일아웃 시 리더 선출/분산락 필요** → 현재 범위 밖, `// SCALE:` 주석으로 표시 권장.

## 6. 로깅 · 모니터링

- 로그 레벨: prod INFO, 도메인 이벤트(상태전환·알람생성·AI호출)는 명시적 INFO 로그.
- **민감정보 마스킹**: 비밀번호·토큰·API 키·SSE 쿼리 token 로그 출력 금지 (보안 명세 §4, §5).
- 헬스: `spring-boot-starter-actuator` → `/actuator/health`(공개), 그 외 엔드포인트는 비노출 or 인증.
- AI 사용량: `ai_reports` 토큰 컬럼 + `/admin/ai-usage`로 비용 추적 (docs/06 §9, NFR-4).
- 에러 응답엔 스택트레이스 미포함(GlobalExceptionHandler 공통 포맷) — 운영 정보 노출 방지.
- 모니터링 대시보드/APM은 과설계 → 채택 안 함. Railway/Vercel 기본 로그로 충분.
