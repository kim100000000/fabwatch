## 1. 배포 아키텍처

```
[사용자 브라우저]
      │ HTTPS
      ▼
[Vercel] ── 프론트(React/Vite 정적 빌드), 도메인 TLS 종단
      │ REST + SSE (HTTPS, CORS 허용 Origin만)
      ▼
[Railway] ── 백엔드(Spring Boot 컨테이너) + MySQL 8 (동일 프로젝트/네트워크)
      │
      ▼ (백엔드 내부 호출만)
[Anthropic Claude API]
```

- 프론트/백엔드 분리 배포. 프론트는 정적 자산, 백엔드는 상시 컨테이너.
- TLS는 Vercel/Railway가 종단 제공 → 애플리케이션은 평문 HTTP 리스닝하되 외부 노출은 HTTPS만 (보안 명세 §4).
- 무료/저비용 티어 전제. 비용 초과 리스크는 §7.

## 2. 환경 & 프로파일

| 환경 | 용도 | 프로파일 | 특이사항 |
|---|---|---|---|
| local | 개발 | `local` | docker-compose MySQL, 시뮬레이터 on, Claude 실키 or 목 |
| test | CI/테스트 | `test` | @Scheduled·시뮬레이터 off, Claude 목 (docs/12 §2) |
| prod | 배포(Railway) | `prod` | 환경변수 주입, 시드는 최초 1회만 |

- Spring: `SPRING_PROFILES_ACTIVE`로 선택. 프론트: Vite `--mode`.
- `application-{profile}.yml`은 커밋하되 **비밀값은 넣지 않는다**(플레이스홀더/환경변수 참조만). `application-local.yml`에 실값이 들어가면 `.gitignore` 대상 (보안 명세 §5).

## 3. 환경변수 목록 (`.env.example`로 커밋 — 키만, 값 없음)

### 백엔드 (Railway)
| 키 | 예시/설명 |
|---|---|
| `SPRING_PROFILES_ACTIVE` | `prod` |
| `DB_URL` | `jdbc:mysql://<host>:<port>/fabwatch?useSSL=true&serverTimezone=UTC` |
| `DB_USERNAME` / `DB_PASSWORD` | Railway MySQL 자격증명 |
| `JWT_SECRET` | 256bit 이상 랜덤 (보안 명세 §2) |
| `JWT_ACCESS_EXP_MIN` | `30` |
| `JWT_REFRESH_EXP_DAYS` | `14` |
| `ANTHROPIC_API_KEY` | 백엔드 전용, 프론트 번들 금지 (보안 명세 §5) |
| `AI_PROVIDER` | `claude`(기본) \| `mock`. mock은 명시 설정했을 때만 — 키가 없다고 자동 mock 금지. 키 없는 claude는 리포트 FAILED |
| `AI_MODEL` | `claude-sonnet-5-5` (기본값) |
| `AI_MAX_TOKENS` | `4096` (사고 토큰 포함 출력 상한) |
| `AI_EFFORT` | `low`(기본) \| `medium` \| `high` — 요청 `output_config.effort`. 잘못된 값이면 기동 실패 |
| `AI_TIMEOUT_SECONDS` | `60` (Claude 응답 읽기 타임아웃, connect는 10초 고정) |
| `SIMULATOR_DEMO_DURATION_MIN` | `2` (데모 자동 시작 DRIFT 지속 시간(분), 선택) |
| `AI_DAILY_QUOTA` | `20` (하루(KST) 전체 호출 시도 수, 초과 시 403 `AI_QUOTA_EXCEEDED`) |
| `CORS_ALLOWED_ORIGINS` | Vercel 도메인 (콤마 구분, `*` 금지) |

### 프론트 (Vercel) — `VITE_` 접두사는 번들 노출 전제 → 공개 가능 값만
| 키 | 설명 |
|---|---|
| `VITE_API_BASE_URL` | `https://<railway-app>/api/v1` |
| `VITE_SSE_BASE_URL` | SSE 엔드포인트 base |

> **커밋 전 필수:** `git status`로 `.env`/`application-local.yml` 미추적 확인. 최초 커밋 전 시크릿이 히스토리에 없는지 점검 (보안 명세 §5, CLAUDE.md).

## 4. 빌드 & 배포 절차

### 백엔드 (Railway)
1. `./gradlew clean build` (테스트 포함) → 실행 가능 jar.
2. 컨테이너 빌드: Dockerfile(다단계) 또는 Railway Nixpacks 자동 감지.
3. 환경변수 주입 → 배포. 헬스체크 `/actuator/health` 통과 확인.
4. **DB 마이그레이션**: MVP는 `ddl-auto=validate`(prod) + 수동 스키마 or Flyway 여유 시. `create/update` 금지(운영에서 스키마 자동 변경은 위험).
5. 시드: prod 최초 1회만 실행되도록 가드(플래그/조건). 시연 데이터가 매 배포마다 중복 생성되지 않게.

### 프론트 (Vercel)
1. Git 연동 → main 푸시 시 자동 빌드(`npm run build`, tsc 포함).
2. 환경변수 설정 후 배포. Preview(브랜치) / Production(main) 분리.

### CI (GitHub Actions — 여유 시, Should)
```
push/PR → ① 백엔드 ./gradlew test  ② 프론트 npm run build(tsc)
         → 통과해야 배포 (Railway/Vercel Git 연동은 별도 자동 배포)
```
- 시크릿은 GitHub Actions Secrets. 로그에 마스킹.

## 6. 로깅 · 모니터링

- 로그 레벨: prod INFO, 도메인 이벤트(상태전환·알람생성·AI호출)는 명시적 INFO 로그.
- **민감정보 마스킹**: 비밀번호·토큰·API 키·SSE 쿼리 token 로그 출력 금지 (보안 명세 §4, §5).
- 헬스: `spring-boot-starter-actuator` → `/actuator/health`(공개), 그 외 엔드포인트는 비노출 or 인증.
- AI 사용량: `ai_reports` 토큰 컬럼 + `/admin/ai-usage`로 비용 추적 (docs/06 §9, NFR-4).
- 에러 응답엔 스택트레이스 미포함(GlobalExceptionHandler 공통 포맷) — 운영 정보 노출 방지.
- 모니터링 대시보드/APM은 과설계 → 채택 안 함. Railway/Vercel 기본 로그로 충분.

## 7. 장애 대응 & 폴백

| 상황 | 대응 |
|---|---|
| Claude API 장애/쿼터 | 리포트 status FAILED + 수동 작성 폴백 (docs/03 F-6.4). 서비스 전체는 정상 동작 |
| SSE 연결 불가(프록시/브라우저) | 3초 폴링 폴백 (docs/07 버퍼 규칙) |
| DB 연결 실패 | 헬스체크 실패 → 재시작. 커넥션 풀 크기·타임아웃은 docs/15 §5 |
| 무료 티어 슬립/콜드스타트 | 시연 전 워밍업 호출. README에 "첫 응답 지연 가능" 명시 |
| 시드 중복/오염 | prod 시드 가드(§4). 오염 시 재시드 절차 문서화 |

## 8. 백업 · 데이터

- MVP: Railway MySQL 자동 백업 티어 확인. 포트폴리오라 RPO/RTO 목표는 두지 않음.
- 데이터 보존 정책은 docs/05 §3(원본 7일 / 집계 영구 / 그 외 soft delete)을 운영에서도 그대로 적용.

## 9. 롤백
