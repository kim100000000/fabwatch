# 08. 수익화 전략 — FabWatch

> 버전 v1.0 / 2026-07-06
> 위치: **취업이 1순위. 이 문서는 "설계"까지만 하고, 실행은 취업 후.**
> 단, MVP 개발 중에도 이 문서의 "지금 해둘 것" 항목만은 반영한다 (나중에 뜯어고치는 비용 방지).

## 0. 전체 그림 — 수익화 3트랙

| 트랙 | 모델 | 시점 | 기대 규모 |
|---|---|---|---|
| A | 중소공장용 경량 설비관리 SaaS | 취업 후 6개월~ | 월 구독, 본명 사업 |
| B | 템플릿/구축형 판매 (코드+문서 패키지) | MVP 완성 직후 가능 | 건당, 부수입 |
| C | 콘텐츠 부수입 (개발기·현장경험 글) | MVP 완성 직후 가능 | 소액+영업 채널 역할 |

세 트랙은 경쟁이 아니라 순서다: **C(글)로 신뢰 → B(템플릿)로 검증 → A(SaaS)로 확장.**

## 0. 알려진 리스크 (실행 전 반드시 재확인)

비판적 검토(2026-08-07) 결과 남겨둔 미해결 항목. A트랙 실행 게이트(A-5) 통과 전 이 항목들을 먼저 좁혀야 한다 — 지금은 "설계"일 뿐 검증된 사업 가설이 아니다.

- **경쟁 분석 없음**: UpKeep/Fiix/MaintainX 등 해외 경량 CMMS, 국내 스마트공장 보급사업 공급기업(이미 다수 등록)과의 실제 기능/가격 비교가 이 문서 어디에도 없다. A-1 "시장 논리"는 근거(설문/인터뷰/공개 통계) 없는 추정이다. → 실행 전 경쟁사 최소 5곳 기능·가격 비교표 작성.
- **AI 기능은 자체 모델/데이터가 아니라 Claude API 래핑**: 프롬프트 조합이 차별점의 전부. Anthropic 가격·정책 변경에 마진이 그대로 노출되고, 동일 API를 쓰는 경쟁사가 며칠 내 복제 가능하다. 진짜 해자가 되려면 축적된 현장 데이터로 자체 이상탐지/분류 모델을 학습하는 로드맵이 필요(현재 07 "다음 단계"에 방향만 있고 계획 없음).
- **유닛 이코노믹스 미검증**: 아래 A-2 원가 추정 참조. 실측 전엔 가격표(A-2)를 확정된 것으로 취급하지 않는다.
- **판로 채널 미검증**: A-4의 정부지원사업·산업단지 네트워크는 창업자의 실제 접근 경로(트랙레코드, 인맥)가 확인된 바 없다. "지인 공장 1곳" 파일럿 확보 전까지 판로는 가설로 취급.
- **실설비 연동 시 안전/책임 공백**: 트랙A가 전제하는 실PLC/Modbus 연동(07 "다음 단계")은 알람→설비 상태 제어가 실제 물리 제어로 격상됨을 의미한다. 지금 MVP의 CRITICAL→DOWN 전환은 DB 필드 변경일 뿐 물리 제어가 아니다(03 F-2 범위 한정 참조). 실제 제어로 확장하려면 기능안전 인증(IEC 61508 등)·SLA·배상 책임 설계가 선행되어야 하며, 이 검토 없이는 실설비 연동에 절대 착수하지 않는다.

## 트랙 A — 중소공장용 SaaS (본명)

### A-1. 왜 중소공장인가 (시장 논리)
- 대기업: MES/CMMS 이미 있음 (SAP PM, 자체 CIM). 진입 불가.
- **50인 이하 중소 제조**: 설비 점검을 아직 엑셀·수기 대장·카톡으로 관리하는 곳이 대부분. 기존 CMMS(국내외)는 이들에게 너무 비싸고 복잡함.
- 페인 포인트(현장에서 직접 본 것): 점검 기록이 사람 머리에만 있음 → 담당자 퇴사 시 증발 / 고장 나면 그때서야 대응 / 정부 스마트공장 지원사업은 있는데 쓸 만한 경량 도구가 없음.
- 진입 각도: "MES 풀세트"가 아니라 **"설비 점검 대장의 디지털 전환"** 딱 하나로 좁혀서 진입. 이 좁힘이 영업 문장 하나로 설명되게 해준다.

### A-2. 가격 설계 (초안)
| 플랜 | 월 가격 | 범위 |
|---|---|---|
| Free | 0원 | 설비 5대, 사용자 2명, 이력 3개월 보관, AI 리포트 월 5건 |
| Starter | 5만원/월 | 설비 30대, 사용자 10명, 이력 무제한, AI 월 50건 |
| Pro | 15만원/월 | 설비 무제한, 사용자 무제한, AI 무제한(공정사용), 센서 연동(게이트웨이) |
| 구축형 | 별도 견적 (300만~) | 온프레미스 설치 + 커스터마이징 (트랙 B와 연결) |

- 근거: 중소공장 결재권자(사장/공장장)가 품의 없이 긁을 수 있는 심리선이 월 5~15만원. (검증 안 됨 — 실제 구매자 인터뷰 없이 정한 추정치)
- AI 리포트가 과금 차별화 축 (원가가 토큰이므로 플랜별 쿼터가 자연스러움).

**원가 개략 추정 (실측 전 추정치, §0 참고)**: 리포트 1건 = Claude API 호출 1회, max_tokens 2000(docs/06). 입력 프롬프트(센서 요약+이력)까지 합치면 호출당 원가는 모델 단가에 직접 비례한다. Starter 플랜(월 5만원, AI 월 50건 쿼터) 기준 리포트당 허용 원가는 "월 매출/50건"에서 인프라비·결제수수료를 뺀 값 — 이 값이 실제 API 단가보다 낮으면 고쿼터 고객일수록 손해다. **가격 확정 전 실제 토큰 사용량으로 리포트 1건당 원가를 측정하고, 원가 대비 최소 3배 마진이 나오는지 확인한다.** 인프라비(Railway/MySQL)도 데모용 가상 라인 1개 기준이라 설비 30대(Starter 상한) 붙었을 때 재계산 필요.

### A-3. 기술 전환 설계 (멀티테넌시)
- 방식: **단일 DB + tenant_id 컬럼** (row-level). 초기엔 이게 정답 — 스키마 분리는 고객 100+ 이후 고민.
- 전환 작업 목록:
  1. `tenants` 테이블 신설 (플랜, 상태, 구독 정보)
  2. `// TENANT:` 주석 붙은 테이블(users, lines, equipments 계열)에 tenant_id 추가
  3. JWT 클레임에 tenantId 포함 → JPA `@Filter` 또는 Hibernate 6 `@TenantId`로 전 쿼리 자동 필터
  4. 가입 온보딩: 회사 생성 → 설비 등록 마법사 (엑셀 업로드 임포트 — 기존 엑셀 대장 이관이 킬러 온보딩)
  5. 결제: 토스페이먼츠 정기결제 (국내 대상이므로 Stripe보다 우선)
- 센서 없는 공장 대응: **센서는 옵션.** 점검 대장 기능만으로 성립하도록 이미 MVP 구조가 분리돼 있음 (센서 NULL 허용 설계가 이 포석).
- 실설비 연동: Pro 플랜용. 라즈베리파이+게이트웨이로 Modbus **수집(읽기)** → REST 푸시 (시뮬레이터와 동일 인터페이스로 이미 추상화). **센서값 읽기까지만 이 문서 범위** — 인터락(CRITICAL 알람 시 설비를 실제로 정지시키는 쓰기/제어)은 별개 항목이며 §0의 안전 리스크가 해소되기 전엔 착수하지 않는다.

### A-4. 판로 (국내 중소 제조 특화)
1. **정부 지원사업 편승**: 스마트공장 보급확대사업, 제조혁신바우처 — 공급기업 등록 시 고객이 정부 돈으로 구매. 취업 후 1순위 조사 항목.
2. 지역 산업단지 커뮤니티, 중소기업중앙회 계열 네트워크.
3. C트랙 콘텐츠 유입 (아래).
4. 지인 공장 1곳 무료 파일럿 → 사례 확보 (사례 없인 제조업 영업 불가).

### A-5. 실행 게이트 (이 조건 되기 전엔 A에 돈/시간 크게 안 쓴다)
- [ ] 취업 완료 + 수습 종료 (본업 안정)
- [ ] 파일럿 공장 1곳이 3개월 이상 실사용
- [ ] "돈 내겠다"는 구두 약속 2곳 이상
- [ ] 경쟁사 최소 5곳 기능·가격 비교 완료 (§0)
- [ ] 리포트 1건당 실측 원가 확인, 가격표 대비 마진 3배 이상 확인 (§0, A-2)
- [ ] (실설비 제어 인터락까지 확장 시에만) 기능안전 인증 요건 검토 완료 — 검토 전엔 쓰기/제어 기능 개발 금지
- 위 조건 전 단계에서는 트랙 B/C만 굴린다.

## 트랙 B — 템플릿/구축형 판매 (취업 후 바로 가능)

### B-1. 상품 구성
| 상품 | 가격(초안) | 내용 |
|---|---|---|
| 문서 패키지 | 3~5만원 | 이 docs 00~08 세트 + 작성 가이드 (포트폴리오 준비생·SI 초년생 대상) |
| 코드 템플릿 | 15~30만원 | FabWatch 전체 소스 + 설치 가이드 + 커스터마이징 포인트 문서 |
| 구축 대행 | 건당 300만~ | 소규모 공장 맞춤 설치 (트랙 A 구축형과 동일) |

### B-2. 채널
- 크몽/탈잉/위시켓 (국내), Gumroad (문서 영문화 시)
- 주의: 포트폴리오 원본과 판매본은 리포 분리. **판매본에는 회사 실명·실데이터 절대 금지** (LG디스플레이 관련 수치·공정 파라미터는 전부 일반화된 가상값 — 이미 MVP 시드가 가상값이라 문제없음. 이 원칙 유지).

### B-3. 리스크
- 영업비밀: 전 직장의 구체적 공정 조건/레시피/실제 알람 코드 체계를 쓰지 않는다. "PM/BM, 4M, 교대" 같은 업계 일반 개념만 사용. (이 문서 기준 현재 안전)
- 겸업: 취업 후 회사 겸업 규정 확인 필수. 위반 소지 있으면 B/C는 무료 공개로 전환하고 A 준비만.

## 트랙 C — 콘텐츠 (영업 채널 겸 부수입)

- 소재가 이미 확보돼 있음: "LGD 테크니션 3년이 개발자로 전직하며 설비관리 시스템을 만든 과정"

## 지금(MVP 개발 중) 해둘 것 — 이것만은 실행

1. `// TENANT:` 주석 규칙 준수 (05 문서 반영 완료)

6. 개발 과정을 스크린샷/메모로 기록 (트랙 C 원고 재료)
