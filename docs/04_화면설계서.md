# 04. 화면 설계서 — FabWatch

> 버전 v1.1 / 2026-10-09 (v1.1: 설비 상태 색 IDLE=노랑·PM=회색으로 변경, S-1 배치도 뷰 추가)

## 1. 공통 디자인 토큰

산업용 모니터링 시스템 무드: 다크 대시보드 + 상태 색 중심. (현장 CIM 모니터 감성)

```css
:root {
  /* 배경 */
  --bg-base: #0F1419;       /* 전체 배경 */
  --bg-card: #1A2129;       /* 카드 */
  --bg-hover: #232B35;
  --border: #2D3742;

  /* 텍스트 */
  --text-primary: #E6EBF0;
  --text-secondary: #8B98A5;

  /* 설비 상태 (현장 표준 색) */
  --status-run: #22C55E;     /* RUN 초록 */
  --status-idle: #FACC15;    /* IDLE 노랑 (v1.1: 회색→노랑) */
  --status-down: #EF4444;    /* DOWN(BM) 빨강 */
  --status-pm: #94A3B8;      /* PM 회색 (v1.1: 파랑→회색) */

  /* 설비 '상태'가 아닌 용도의 보조 색 (상태 토큰 값 변경의 영향을 받지 않게 분리) */
  --neutral: #94A3B8;        /* 일반 중립 회색 */
  --pm-task: #3B82F6;        /* 점검 유형 PM · PM 지연 표시 파랑 */

  /* 알람 심각도 */
  --alarm-warning: #F59E0B;
  --alarm-major: #F97316;
  --alarm-critical: #DC2626;

  --accent: #06B6D4;         /* 포인트 (버튼/링크) */
  --radius: 8px;
  --font: 'Pretendard', sans-serif;
  --font-mono: 'JetBrains Mono', monospace;  /* 센서 수치용 */
}
```

- 차트: Recharts. 센서 라인 `--accent`, 임계치 warn 점선 `--alarm-warning`, crit 점선 `--alarm-critical`.
- 수치는 모두 mono 폰트 (자릿수 흔들림 방지).
- 반응형: 데스크톱 우선, 1024px 이하에서 카드 2열→1열. 점검 입력 폼은 태블릿(현장 사용) 고려해 터치 타겟 44px 이상.

## 3. 핵심 화면 상세

### S-1 라인 현황 대시보드
```
┌───────────────────────────────────────────────┐
│ 헤더: 로고 | 라인선택 | 교대(D/N) 표시 | 사용자 │
├───────────────────────────────────────────────┤
│ 상태 카운트(RUN/IDLE/DOWN/PM/미조치 알람)          │
│ 라인 KPI: 가동률 | MTBF | MTTR | DOWN 횟수 (일/주/월) │
├──────────────┬──────────────┬─────────────────┤
│ [LAMI-01]    │ [LAMI-02]    │ [SCRB-01]  ...  │
│ ● RUN        │ ● RUN        │ ● DOWN          │
│ 45.2℃ 2.1mm/s│ ...          │ 알람 2 ⚠        │
│ −94.8kPa 12A │              │ PM지연 배지     │
├──────────────┴──────────────┴─────────────────┤
│ 실시간 알람 스트림 (최근 10건, SSE 추가)        │
└───────────────────────────────────────────────┘
```
- 설비 카드: 상태 좌측 보더 4px 색상. 클릭 → S-3. 센서값은 2초마다 갱신(SSE), 임계치 초과값은 해당 심각도 색으로 깜빡임 1회.
- 데모 컨트롤(우하단 플로팅, ENGINEER+): 기본은 접힌 알약 버튼, 펼치면 폭 280px 컴팩트 패널.
  - **헤더 드래그(마우스/터치)로 이동** — 뷰포트 안으로 제한, 윈도 리사이즈 시 재제한, 위치는 localStorage 에 기억. 헤더에 포커스 후 방향키(Shift=크게)로도 이동, Home/↺ 버튼으로 위치 초기화, Esc/✕ 로 접기. 배치도를 가리면 옮겨 둘 수 있다.
  - 주 동작은 **데모 자동 시작**(약 2분: 경고 → 위험 → 자동 DOWN). 활성 시나리오 목록·해제 버튼을 바로 아래에 둔다.
  - 센서/시나리오 수동 주입은 접이식 **수동 주입(고급)** 섹션. 센서가 없는 설비는 선택 불가, 설비에 없는 센서 종류는 목록에 나오지 않는다. DRIFT 는 지속시간(2/5/10분, 기본 2분)을 고르며 안내 문구에 반영한다(과거 기본 10분은 시연 때 변화가 안 보여 혼란).

#### S-1 배치도 뷰 (설비 레이아웃)

설비 카드 그리드 위에 **라인을 공정 순서대로 한 줄 흐름으로 그린 설비 배치도**를 둔다. 대시보드의 "설비 현황" 헤더에 **배치도 / 카드** 보기 전환 토글(기본=배치도, 선택은 localStorage에 보관, 실패해도 동작)이 있고 카드 그리드는 그대로 유지한다. 순수 SVG/CSS로 그리며 외부 라이브러리를 쓰지 않는다. API 변경은 없다(기존 설비·센서·알람·PM 지연·`GET /lines`(공정 seq) 응답을 조합).

**배치**
- 좌표를 저장하지 않는 자동 배치: 라인별로 한 줄(가로) → 공정 구역(헤더에 순번+공정명, 예: 1 합착 → 2 절단 → 3 검사) → 구역 안 설비는 code 순(숫자 자연 정렬). 공정 순서는 `GET /lines`의 공정 `seq`, 없으면 processId 오름차순. 헤더 라인 선택(lineId)을 그대로 따른다.
- 설비 사이(공정 경계 포함)에 컨베이어 화살표. **양쪽 설비가 모두 RUN일 때만** 초록 점선이 흐르고 나머지는 회색 정지.
- 설비 종류는 code 접두사로 판별하는 **가상 일반형** 4종 — LAMI(합착기)·OVEN(경화로)·SCRB(스크라이버)·AOI(검사기). 모르는 접두사는 범용 박스. 지붕 장식·상단 스트립으로 종류를 구분하는 단순 기하 도형이며 실제 설비 구조·수치와 무관하다.

**설비 상태 = 본체 색** (토큰 `--status-*` 단일 출처, 4개 상태만 — PD 상태 없음)

| 상태 | 본체 색 | 박스 안 라벨 |
|---|---|---|
| RUN | 초록 `--status-run` | RUN |
| IDLE | 노랑 `--status-idle` | IDLE |
| PM | 회색 `--status-pm` | PM |
| DOWN | 빨강 `--status-down` | DOWN (BM) |

**알람 = 외곽 링 + 모서리 뱃지 (본체 색은 바꾸지 않는다)**

| 최고 심각도 | 링 | 뱃지(우상단) |
|---|---|---|
| WARNING | 주황 `--alarm-warning`, **점선** 3px | ▲ 경고 N |
| MAJOR | 진한 주황 `--alarm-major`, **실선 두 겹** | ▲ 주요 N |
| CRITICAL | 빨강 `--alarm-critical`, **굵은 실선 두 겹** | ⊗ 위험 N |

- 링 심각도·알람 건수 뱃지는 **PM 지연(PM_OVERDUE) 알람을 제외한 센서/수동 알람 기준**이다(PM 지연은 전용 뱃지가 있고, 섞이면 WARNING→CRITICAL 변화가 MAJOR에 가려진다). PM 지연 알람 건수는 툴팁에 별도로 표시한다.
- 미확인(OPEN)이 하나라도 있으면 링이 깜빡이고(CRITICAL은 더 빠르게) 뱃지가 채워진다. 전부 확인(ACK)이면 깜빡임 없이 정지하고 뱃지가 윤곽만 남는다.
- IDLE 노랑 본체와 WARNING 주황 링은 색 외에 **링 모양(점선·본체와 간격)과 ▲ 뱃지·글자**로도 구분한다.
- PM 지연: 좌상단 뱃지(시계 아이콘 + "PM 지연", `--pm-task` 파랑).
- 센서 수신 끊김(최근 측정 15초 초과): 설비가 흐려지고 중앙 `?` 아이콘 + 하단 "수신 끊김" 글자.

**센서 → 파트 매핑** (본체 안 파트 4슬롯)

| 센서 | 파트(슬롯) | 비고 |
|---|---|---|
| TEMP | 히터/챔버부 (좌상) | WARNING→주황 / CRITICAL→빨강으로 **해당 파트만** 색 변경 + "히터 경고/위험" 라벨 |
| VIBRATION | 구동 모터부 (우상) | 〃 "모터 …" |
| PRESSURE | 진공/에어부 (좌하) | 〃 "진공 …" |
| CURRENT | 전장 제어부 (우하) | 〃 "전장 …" |

센서가 없는 종류(예: AOI·OVEN의 압력)는 점선 빈 슬롯으로 둔다.

**상호작용**
- 호버/포커스 = 툴팁(설비명·코드·상태 라벨·센서 4값+단위·미해결 알람 건수/최고 심각도·미확인 건수·PM 지연·끊김). Esc로 닫음.
- 클릭/Enter = 설비 상세(S-3, `/equipment/:id`)로 이동.
- 하단에 범례(상태 4색 · 알람 링 3단계 · 뱃지/파트 의미).

**접근성**
- 색만으로 구분하지 않는다: 상태 라벨 텍스트 상시 표기, 알람·PM 지연·끊김·파트 이상은 아이콘 + 글자, 설비 박스 `aria-label`에 상태·알람·PM 지연·끊김·이상 파트를 모두 문장으로 포함.
- 설비 박스는 `button`(키보드 포커스·포커스 링 3px). `prefers-reduced-motion`이면 컨베이어 흐름·링 깜빡임을 정지하고 정적 표시(초록 점선 고정, 링 항상 켜짐, 미확인은 채운 뱃지)로 대체.
- 390px 모바일: 배치도 컨테이너만 가로 스크롤, 페이지 전체 가로 스크롤 없음.

### S-3 설비 상세
- 상단: 설비 정보 + 상태 변경 버튼(권한별) + "AI 리포트 생성" 버튼(미해결 알람 있을 때 활성).
- 탭1 센서: 4개 실시간 차트(2×2 그리드) + 기간 선택 이력 차트.
- 탭2 점검: 해당 설비 이력 테이블 + PM 스케줄 카드(다음 예정일, OVERDUE 시 PM 파랑 `--pm-task` 강조).
- 탭3 알람: 알람 테이블 (OPEN 상단 고정, ACK/RESOLVE 버튼 인라인).
- 탭4 리포트: 리포트 카드 목록 (DRAFT 노란 배지 / CONFIRMED 초록).

### S-5 점검 이력 등록
- 유형 토글(PM/BM)에 따라 폼 분기:
  - PM 선택 → 해당 설비 체크리스트 자동 로드, 항목별 OK/NG/NA 라디오 + 메모.
  - BM 선택 → 4M 분류 셀렉트(필수) + 연계 알람 드롭다운(해당 설비 OPEN/ACK 알람).
- 시작/종료 datetime → 소요시간 자동 표시. 교대조 자동 판정(수정 가능).
- 저장 성공 → 목록 이동 + 토스트. NG 포함 시 "엔지니어 확인 대상으로 표시됩니다" 안내.

### S-7 AI 리포트 상세

│ 제목 | 상태배지(DRAFT/CONFIRMED)     │
